# Спецификация: Виджет «Сравнение товаров»

## Тип задачи
Виджет, встроенный в страницу каталога. Роутинг не затрагивается — в проекте
маршрутизация отсутствует (зависимости ограничены `react` и `react-dom`),
поэтому раздел «навигация» не применим.

## Сущности

- **Товар** (существует) — `src/entities/product/model/types.ts`:
  `{ id: string, title: string, category: ProductCategory, price: number,
  characteristics: Record<string, string> }`.
  Характеристики уже содержатся в объекте товара, отдельной загрузки не требуют.
- **Список сравнения** (новая) — `{ productIds: string[], максимум: 3 }`.
  Хранит идентификаторы, а не копии товаров: полные данные берутся из уже
  загруженного каталога.
- **Строка сравнения** (производная, только для отображения) —
  `{ label: string, values: (string | null)[] }`, где `null` означает, что
  у конкретного товара такой характеристики нет.

## Пользовательские действия

1. **Добавить товар к сравнению** — триггер: кнопка на карточке товара
   (`ProductCard` уже имеет слот `footer` для такой кнопки), результат: id товара
   попадает в список сравнения, если лимит не превышен.
2. **Убрать товар из сравнения** — триггер: кнопка в столбце товара внутри
   таблицы сравнения, результат: товар удаляется, таблица перестраивается
   (набор строк пересчитывается, так как часть характеристик могла быть только
   у удалённого товара).
3. **Попытка добавить 4-й товар** — триггер: та же кнопка на карточке товара,
   результат: уведомление о достижении лимита, состав списка НЕ меняется.
4. **Убрать товар с карточки** — триггер: та же кнопка на карточке уже
   добавленного товара, результат: товар исчезает из сравнения (решение №4 —
   кнопка работает как переключатель, поэтому у неё два состояния и два текста).

## Состояния экрана/компонента

- **Загрузка** — применимо, хотя в постановке не описано. Возникает реально:
  список сравнения восстанавливается из хранилища мгновенно (только id), а
  каталог товаров грузится асинхронно (`useProducts`, задержка 700 мс). До
  завершения загрузки развернуть id в данные товаров невозможно.
  Решение: скелетон таблицы (решение №2).
- **Пусто** — 0 или 1 товар в списке: заглушка с предложением добавить ещё
  товары. Постановка описывает единый текст для обоих случаев.
- **Успех** — 2 или 3 товара: таблица, характеристики построчно, товары по
  столбцам.
- **Ошибка** — в постановке не описано. В текущей реализации каталог умеет
  падать (`fetchProducts` отклоняется, виджет каталога показывает `EmptyState`
  с кнопкой повтора). Собственного сообщения об ошибке у виджета сравнения нет —
  см. предположение ниже.
- **Частичные данные** — ключевое состояние для этой задачи, встречается в двух
  разных видах:
  - у товаров **разные наборы характеристик** (подтверждено данными: у
    `Ноутбук Forge 16 Gaming` есть «Видеокарта» и «Подсветка», у остальных
    ноутбуков их нет) — решение №1: объединение с прочерком;
  - в хранилище лежит **id товара, которого больше нет** в загруженном каталоге
    — решение №3: id отбрасывается.

## Технические ограничения

- **Персистентность — `sessionStorage`** (решение №5): переживает перезагрузку
  вкладки, сбрасывается при её закрытии. `localStorage` противоречил бы
  постановке, так как дал бы сохранение между сессиями.
- **Лимит — 3 товара одновременно**, задан жёстко.
- Виджет работает с уже загруженными данными каталога, собственных сетевых
  запросов не делает.

## Интеграции (API)

Новых интеграций не требуется. Источник данных — существующий
`fetchProducts()` (`src/entities/product/api/productsApi.ts`), отдающий мок со
всеми характеристиками. Контракт известен, дополнительный эндпоинт за
характеристиками не нужен.

## Решения по критичным вопросам

Получены от постановщика 2026-09-20, стадия разблокирована.

1. **Разные наборы характеристик — объединение с прочерком.** Таблица строится
   по объединённому множеству ключей всех выбранных товаров; если у товара
   характеристика отсутствует, в ячейке выводится прочерк. Следствие: набор
   строк зависит от состава сравнения и пересчитывается при каждом
   добавлении/удалении.
2. **Пока каталог грузится — скелетон таблицы.** Виджет не ждёт молча и не
   мигает заглушкой «пусто».
3. **Id без соответствующего товара — отбрасывается.** Молча, без уведомления.
   Следствие, которое надо учесть на следующих стадиях: отбрасывание может
   уменьшить число товаров до одного и перевести виджет в состояние «пусто» —
   это ожидаемое поведение, а не дефект.
4. **Кнопка на карточке переключает состояние.** Повторное нажатие убирает товар
   из сравнения. Следовательно, кнопка имеет два визуальных состояния и два
   текста, а действие «убрать товар» доступно из двух мест — из таблицы и с
   карточки.
5. **Персистентность — `sessionStorage`.** Сравнение переживает перезагрузку
   вкладки и сбрасывается при её закрытии. Механизм хранения нужен.

## Открытые вопросы

### Некритичные (можно уточнить позже)

1. В каком порядке товары идут в столбцах таблицы — по времени добавления, по
   цене, по порядку в каталоге? Умолчание — по времени добавления.
2. Нужна ли кнопка «очистить всё сравнение» одним действием?
3. Где именно на странице располагается виджет — над сеткой товаров, под ней или
   в виде закреплённой панели? Влияет на вёрстку, но не на логику.
4. Нужно ли подсвечивать различия между товарами (например, выделять строки, где
   значения не совпадают)? В постановке не упомянуто.
5. Поведение таблицы на узких экранах: горизонтальная прокрутка столбцов при
   зафиксированной колонке с названиями характеристик — или иное решение.

## Предположения (если делались)

- **Виджет не делает собственных запросов**, а использует товары, уже
  загруженные каталогом. Обоснование: поле `characteristics` входит в тип
  `Product` и приходит вместе со списком — отдельный эндпоинт за
  характеристиками не нужен. Проверено по коду, не додумано.
- **Кнопка добавления размещается в существующем слоте `footer` компонента
  `ProductCard`.** Обоснование: слот уже предусмотрен в карточке и пока не
  используется, то есть менять контракт компонента не придётся.
- **Для уведомления о лимите используется существующий `ToastProvider`/`useToast`
  из UI-kit.** Обоснование: постановка требует уведомление, не блокирующее
  основной UI; в проекте уже есть подходящий механизм с автоскрытием.
- **При ошибке загрузки каталога виджет сравнения не показывает собственного
  сообщения.** Обоснование: постановщик ответил про состояние загрузки
  (скелетон), но про ошибку явно не высказался. Каталог уже показывает
  `EmptyState` с кнопкой повтора; дублирующее сообщение рядом с ним создало бы
  два разных сообщения об одной и той же проблеме. Помечено как предположение —
  подлежит подтверждению, если дизайн потребует иного.
