# План UX: Виджет «Сравнение товаров»

Основан на `spec.md` (все критичные вопросы закрыты). Макетов нет, визуальный
язык берётся из существующего UI-kit `src/shared/ui` и токенов
`src/shared/styles/tokens.css`. Storybook в проекте отсутствует, поэтому
инвентаризация примитивов сделана по публичному API `src/shared/ui/index.ts`.

## Доступные примитивы UI-kit

| Примитив | Варианты | Пригодность для задачи |
| --- | --- | --- |
| `Button` | `primary` / `secondary` / `ghost`, `sm` / `md`, `block` | кнопка-переключатель на карточке, удаление столбца |
| `Card` + `CardBody` | `interactive` | поверхность виджета |
| `EmptyState` | `neutral` / `error`, `title`, `description`, `action` | заглушка «добавьте ещё товары» |
| `Skeleton` | `width`, `height`, `radius` | скелетон таблицы на время загрузки |
| `TextField` | — | не применим |
| `ToastProvider` / `useToast` | `info` / `warning` | уведомление о достижении лимита |

## Дерево компонентов

```
ComparisonWidget                        (корень, решает, какое состояние показать)
├── ComparisonTableSkeleton             новый — композиция <Skeleton>
├── EmptyState                          → переиспользует <EmptyState variant="neutral">
│                                         («Выберите минимум два товара»)
└── ComparisonTable                     новый — состояния «успех» (2-3 товара)
    ├── ComparisonColumnHeader[]        новый — заголовок столбца товара
    │   └── Button (ghost, sm)          → переиспользует, действие «убрать из сравнения»
    └── ComparisonRow[]                 новый — строка характеристики

ProductCard (существует, слот footer)
└── ToggleComparisonButton              новый — фича, обёртка над <Button>
                                          состояние «добавить»  → variant="secondary"
                                          состояние «в сравнении» → variant="primary"
```

Весь виджет размещается внутри `<Card>` — та же поверхность, что у карточек
товаров, поэтому отдельный фон и рамку изобретать не требуется.

## Связь состояний экрана с визуальным представлением

| Состояние из spec.md | Что показывает виджет |
| --- | --- |
| Загрузка каталога | `ComparisonTableSkeleton`: колонка названий характеристик и 2-3 колонки значений, собранные из `<Skeleton>` разной ширины |
| Пусто (0-1 товар) | `<EmptyState>` с заголовком и пояснением, без кнопки действия — добавление происходит на карточках товаров, а не внутри виджета |
| Успех (2-3 товара) | `ComparisonTable` |
| Ошибка загрузки каталога | виджет не рендерится: сообщение об ошибке уже показывает каталог (предположение из spec.md) |
| Частичные данные: нет характеристики | ячейка с прочерком «—» цветом `--color-text-muted` |
| Частичные данные: неизвестный id | столбец не строится, id отбрасывается молча |
| Лимит достигнут | `useToast(..., 'warning')` — поверх интерфейса, основной UI не блокируется |

## Используемые design tokens

- `--space-lg` — промежуток между столбцами товаров и отступ виджета от сетки каталога
- `--space-sm` — внутренние отступы ячеек
- `--color-border` — разделители строк таблицы и вертикальные границы столбцов
- `--color-surface` — фон залипающей колонки с названиями характеристик
- `--color-text-muted` — прочерк в пустой ячейке и подписи характеристик
- `--font-size-sm` — подписи характеристик
- `--radius-md` — скругление поверхности виджета (наследуется от `Card`)

Новых токенов не требуется.

## Новые компоненты (обоснование)

- **`ComparisonTable`** — в UI-kit нет табличного примитива. Сравнение с
  построчными характеристиками и прочерками — специфика этой задачи, а не общий
  переиспользуемый примитив, поэтому компонент остаётся в слое виджета.
- **`ComparisonRow`** — строка «название характеристики + значения по товарам»,
  включая отрисовку прочерка. Выделена отдельно, потому что именно её поведение
  проверяется тестами на разнородные наборы характеристик.
- **`ComparisonColumnHeader`** — заголовок столбца: название товара, цена и
  кнопка удаления. Композиция из существующего `Button`, собственного стиля
  почти не требует.
- **`ComparisonTableSkeleton`** — композиция `Skeleton`, повторяющая сетку
  таблицы. Новый визуальный стиль не вводится.
- **`ToggleComparisonButton`** — обёртка над `Button`, переключающая состояние и
  показывающая toast при достижении лимита. Живёт в слое `features`, так как
  содержит поведение, а не только отображение.

## Не покрыто существующим UI-kit (риск для следующей стадии)

1. **Нет табличного примитива с залипающей первой колонкой.** На узких экранах
   нужна горизонтальная прокрутка столбцов товаров при зафиксированной колонке
   названий характеристик. Придётся верстать вручную (`position: sticky`) внутри
   виджета. Кандидат на вынос в UI-kit, если подобные таблицы появятся ещё где-то —
   сейчас выносить преждевременно.

2. **`Toast` не умеет подавлять дубликаты.** При быстрых повторных нажатиях на
   кнопку четвёртого товара пользователь получит стопку одинаковых уведомлений:
   `ToastProvider` складывает их в список и гасит каждое по своему таймеру.
   Решение — на архитектурной стадии: либо подавлять повтор на уровне логики
   сравнения, либо доработать `ToastProvider`. Менять UI-kit ради одного виджета
   нежелательно.

3. **`EmptyState` не имеет компактного варианта.** У него фиксированные отступы
   `--space-xl`, рассчитанные на пустую страницу. Внутри виджета над сеткой
   товаров заглушка займёт заметную высоту. Либо принимаем это, либо на
   архитектурной стадии добавляем в `EmptyState` проп размера — второе
   затрагивает общий UI-kit и требует отдельного решения.

4. **Расположение виджета на странице не определено** (некритичный вопрос №3 из
   spec.md). Умолчание для проектирования: виджет размещается над сеткой товаров,
   сразу под заголовком страницы каталога.
