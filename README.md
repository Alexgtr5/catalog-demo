# Каталог товаров

Демо-приложение каталога электроники на React + TypeScript + Vite.
Служит основой для прогона пайплайна фронтенд-разработки на Claude Code skills.

Стенд: https://catalog-demo-tyulin.vercel.app/

## Быстрый старт

```bash
git clone https://github.com/Alexgtr5/catalog-demo.git
cd catalog-demo
npm ci
```

Дальше нужны два процесса в разных терминалах — каталог берёт товары из API,
без него страница покажет состояние ошибки:

```bash
npm run dev:api   # http://localhost:3000
npm run dev       # http://localhost:5173
```

Нужен Node.js 22 или новее.

## Команды

| Команда | Назначение |
| --- | --- |
| `npm run dev` | Дев-сервер фронтенда на http://localhost:5173 |
| `npm run dev:api` | API в режиме перезапуска на http://localhost:3000 |
| `npm run build` | Проверка типов и продакшн-сборка всех воркспейсов |
| `npm run preview` | Локальный просмотр собранного фронтенда |
| `npm run typecheck` | Только проверка типов |
| `npm run lint` | oxlint |
| `npm test` | Тесты (vitest + testing-library) |

Общие пакеты собираются раньше приложений — npm запускает воркспейсы в порядке
объявления, а не по зависимостям, поэтому шаг `build:packages` вынесен явно.

## Структура

Репозиторий — монорепо на npm workspaces:

```
apps/web/                 фронтенд на React + Vite
apps/api/                 сервис каталога на NestJS + Fastify
packages/contracts/       типы, общие для фронтенда и бэкенда
api/                      обёртка сервиса в serverless-функцию Vercel
```

Фронтенд следует Feature-Sliced Design:

```
apps/web/src/
├── app/                        точка сборки приложения и провайдеры
├── pages/catalog/              страница каталога, загрузка товаров
├── widgets/catalog/            виджет сетки товаров и её состояния
├── widgets/comparison/         виджет сравнения: таблица и скелетон
├── features/filter-products/   фильтрация по категории и поиск
├── features/toggle-comparison/ кнопка добавления товара к сравнению
├── entities/product/           модель товара, загрузка данных, карточка
├── entities/comparison/        список сравнения, лимит, sessionStorage
└── shared/                     UI-kit, дизайн-токены, утилиты
```

Правило импортов — слой обращается только к слоям ниже себя.

Бэкенд разложен по слоям гексагональной архитектуры:

```
apps/api/src/
├── catalog/api/              контроллеры и DTO — единственный слой, знающий про HTTP
├── catalog/application/      сценарии использования
├── catalog/domain/           контракт репозитория, не знает про способ хранения
├── catalog/infrastructure/   реализация репозитория, сейчас in-memory
├── common/                   фильтр ошибок, интерсептор логов, общие DTO
├── config/                   разбор и валидация переменных окружения
└── health/                   пробы живости и готовности
```

## API

```bash
npm run dev:api
```

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/api/v1/products?category=&search=` | Список товаров в конверте `{ items, total }` |
| `GET` | `/api/v1/products/:id` | Карточка товара, 404 при отсутствии |
| `GET` | `/api/health/live` | Проба живости |
| `GET` | `/api/health/ready` | Проба готовности (Terminus) |

Swagger — http://localhost:3000/docs, в продакшн-режиме не поднимается.
Переменные окружения описаны в `apps/api/.env.example`; они валидируются на
старте, и при некорректном значении процесс не поднимется.

Ошибки всех видов приводятся к одному формату (`ApiErrorResponse` в
`packages/contracts`) с `requestId`, который совпадает с идентификатором запроса
в логах. Доменные ошибки не знают про HTTP — в статусы их переводит глобальный
фильтр.

Хранилище спрятано за абстрактным классом `ProductRepository`, который служит
DI-токеном: переход на СУБД меняет одну строку в `catalog.module.ts` и не
затрагивает сценарии.

## Деплой

Стенд целиком живёт на Vercel: статика фронтенда плюс serverless-функция
`api/[...path].mjs`, в которую попадает весь `/api/*`. Функция не содержит
логики — она поднимает то же приложение через `createApp()` и передаёт ему
запрос. Домен один, поэтому CORS в схеме не участвует.

Это компромисс демо-стенда, а не рекомендация. В serverless не работает
ровно то, ради чего сервис написан как долгоживущий процесс: пробы готовности
некому опрашивать, graceful shutdown нечего завершать, пул соединений к БД
живёт не дольше вызова. Поэтому основной способ запуска — контейнер, и
`Dockerfile` собирается из корня репозитория (сервису нужен и
`packages/contracts`, и общий lock-файл):

```bash
docker build -f apps/api/Dockerfile -t catalog-api .
docker run --rm -p 3000:3000 catalog-api
```

Хостинг слушает `PORT` из окружения, поэтому платформа подставит свой сам.
Путь для проб — `/api/health/ready`. Переезд на контейнерный хостинг сводится
к удалению папки `api/` и добавлению `rewrites` в `vercel.json`.

## Данные

Фронтенд запрашивает каталог у API относительным путём `/api/v1/products`:
в разработке его проксирует Vite (цель переопределяется переменной `API_TARGET`),
в продакшне запрос должен попадать на API через тот же домен.

Источник товаров — `apps/api/src/catalog/infrastructure/products.seed.ts`.
Базы данных пока нет: репозиторий держит товары в памяти процесса, и при
перезапуске всё возвращается к исходному набору. Наборы характеристик у товаров
намеренно разные: у части товаров есть поля, которых нет у других.

Состояние ошибки проверяется без правок кода — добавьте `?fail=1` к адресу
страницы; запрос в сеть при этом не уходит. Второй способ увидеть то же
состояние — просто не запускать API.

Фильтрация по категории и поиск пока выполняются на клиенте по уже загруженному
списку. API умеет фильтровать сам (`?category=`, `?search=`), но фронтенд эти
параметры не использует — перенос фильтрации на сервер меняет UX (дебаунс,
отдельные состояния загрузки) и стоит отдельного решения.

## Пайплайн разработки на Claude Code skills

В `.claude/skills/` лежат шесть скиллов — они подхватываются автоматически при
запуске Claude Code из корня проекта, ставить ничего не нужно.

| Стадия | Что делает | Артефакт |
| --- | --- | --- |
| `fe-requirements-intake` | Разбирает ФТТ на сущности, действия и состояния экрана | `spec.md` |
| `fe-ux-scaffolding` | Строит дерево компонентов на существующем UI-kit | `design-plan.md` |
| `fe-architecture-planning` | Принимает техрешения по прецедентам репозитория | `adr.md` |
| `fe-implementation` | Пишет код строго по ADR | код |
| `fe-quality-gate` | Тесты на поведение + typecheck/lint/тесты | тесты и отчёт |
| `fe-delivery` | Ветка, коммиты, PR, деплой, smoke-check | PR и `handoff-report.md` |

### Как прогнать свою ФТТ

```bash
claude
```

Затем в диалоге вызвать первую стадию, передав текст постановки:

```
/fe-requirements-intake <текст ФТТ>
```

Дальше стадии запускаются по одной — каждая проверяет наличие артефакта
предыдущей и отказывается работать без него.

Стадии с первой по пятую работают локально и прав на репозиторий не требуют.
Последняя, `fe-delivery`, пушит ветку и открывает PR — для неё нужен форк
(кнопка Fork на GitHub) либо права на запись. Стенд деплоится на Vercel по
GitHub-интеграции: в форке нужно завести свой проект на vercel.com и указать
этот репозиторий, настройки сборки Vercel возьмёт из `vercel.json`.

Две особенности, которые выглядят как сбой, но заложены по замыслу:

- **Стадия требований останавливает процесс**, если нашла критичный пробел в
  постановке (обычно — отсутствие контракта API или неоднозначность ключевого
  сценария). Это не ошибка: скилл не должен додумывать требования за аналитика.
  Ответьте на вопросы — и он продолжит.
- **Quality gate блокирует доставку** при любой красной проверке и запрещает
  подгонять тест под неверное поведение — вместо этого возвращает на стадию
  реализации.

### Разобранный пример

`docs/product-comparison/` — полный прогон на ФТТ «Сравнение товаров»: все
четыре артефакта, включая зафиксированные открытые вопросы и отклонённые
альтернативы. Результат прогона — слайсы `entities/comparison`,
`features/toggle-comparison`, `widgets/comparison` и
[PR #1](https://github.com/Alexgtr5/catalog-demo/pull/1).

Чтобы начать с чистого состояния — без виджета сравнения, но уже со скиллами:

```bash
git checkout -b my-run pipeline-start
```
