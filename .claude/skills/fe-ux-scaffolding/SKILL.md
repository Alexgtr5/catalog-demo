# UX-заготовка без макетов (UX Scaffolding)

## Назначение
Закрыть главный риск задачи "нет дизайнов": построить структуру интерфейса
(дерево компонентов) на основе существующей дизайн-системы проекта, не
изобретая визуальный дизайн с нуля и не блокируя разработку из-за отсутствия
макетов.

## Предусловие
Должен существовать `spec.md` от стадии `fe-requirements-intake` без
критичных открытых вопросов. Если критичные вопросы есть — остановись и
верни пользователя к предыдущей стадии.

## Инструкции

1. **Просканируй существующий UI-kit / дизайн-систему проекта**:
   - Найди Storybook (`.storybook/`, файлы `*.stories.tsx`) или каталог
     переиспользуемых компонентов (обычно `src/shared/ui`, `src/components`,
     `src/design-system`).
   - Составь список доступных примитивов: карточки, кнопки, иконки, состояния
     загрузки/пустоты/ошибки (Skeleton, EmptyState, ErrorState и т.п.), формы.
   - Найди design tokens: файлы переменных (`tokens.css`, `theme.ts`,
     tailwind-конфиг) — цвета, отступы, типографику.

2. **Построй дерево компонентов** для задачи из spec.md:
   - Для каждого пользовательского действия и состояния экрана определи, какой
     узел дерева за него отвечает.
   - Явно отметь для каждого узла: "переиспользует {компонент} из UI-kit" ИЛИ
     "новый компонент, обоснование: {почему нет подходящего примитива}".

3. **Не создавай новый визуальный стиль**. Если для чего-то нет готового
   компонента — предложи минимальную композицию из существующих примитивов,
   и только если это невозможно — зафиксируй как риск ("требуется новый
   примитив в UI-kit") для решения на архитектурной стадии.

4. **Свяжи каждое состояние экрана из spec.md** (загрузка/пусто/успех/ошибка)
   с конкретным визуальным представлением через существующие компоненты.

5. Сформируй `design-plan.md` по шаблону `templates/design-plan-template.md`.

## Формат вывода
Файл `design-plan.md`: дерево компонентов, список использованных design
tokens, раздел "Не покрыто существующим UI-kit" (риски для следующей стадии).

## Масштабирование
- **UI-kit компонент** (сам является примитивом) — вместо дерева компонентов
  опиши варианты (variants/sizes/states) и как компонент вписывается в
  существующую систему именования и структуру UI-kit.
- **Виджет** — дерево из 3-7 узлов, без разделов навигации.
- **Страница** — полное дерево, включая layout/грид верхнего уровня.
