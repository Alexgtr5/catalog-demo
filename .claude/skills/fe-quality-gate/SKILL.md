# Проверка качества (Quality Gate)

## Назначение
Убедиться, что реализация соответствует спецификации и не содержит явных
дефектов, прежде чем код попадёт в git-flow и на дев-стенд. Эта стадия
блокирующая: при провале любой проверки процесс не идёт дальше.

## Инструкции

1. **Напиши тесты на поведение, а не на реализацию** (React Testing Library
   или аналог, уже используемый в проекте):
   - Для каждого пользовательского действия из `spec.md` — тест-сценарий.
   - Для каждого состояния (загрузка/пусто/успех/ошибка) — отдельная
     проверка рендера.
   - Используй запросы по роли/тексту/aria (`getByRole`, `getByLabelText`),
     а не по CSS-классам, если проект не диктует иное.

2. **Запусти автоматические проверки** (через bash, реальное выполнение,
   не имитация):
   ```
   npx tsc --noEmit
   npx eslint {изменённые пути} --max-warnings=0
   npx {test-runner проекта} {изменённые пути}
   ```
   Определи фактические команды из `package.json` проекта, если они
   отличаются от приведённых по умолчанию.

3. **Если любая проверка падает**:
   - Попробуй исправить очевидные проблемы (форматирование, типы) сам.
   - Если ошибка указывает на логический дефект (тест показывает, что
     поведение не соответствует spec.md) — вернись к стадии
     `fe-implementation`, а не подгоняй тест под неверное поведение.
   - Не помечай стадию как пройденную, если есть красные проверки.

4. Сформируй краткий отчёт: какие тесты написаны, какие проверки пройдены/
   провалены, что было исправлено автоматически.

## Формат вывода
Файлы тестов рядом с реализацией + текстовый отчёт о статусе проверок
(pass/fail по каждому пункту). Только при полностью зелёном отчёте разрешён
переход к стадии `fe-delivery`.
